# TypeScript/React Pain Points

| Done | Priority | Area                            | Pain                                                                                                                               | Evidence                                                                                                                      | Risk                                                                                                         | Fix                                                                                                                    |
|------|----------|---------------------------------|------------------------------------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------|
| [x]  | P0       | Production editor state         | Derived imports/local usage/export amounts were stored and synchronized via Effects.                                               | `ProductionLineApp` recalculated imports in an idle Effect and copied derived usage/export fields back into `productionRows`. | Rendered values and saved values could drift, especially when saving immediately after edits.                | Added a pure production plan selector and render/save from the same calculated rows/imports.                           |
| [x]  | P0       | Save flow                       | Payload mapping, ajax, id lookup, power calculation, and alerting were mixed in `SaveService`.                                     | `saveProductionLineData` built every table payload and posted it in one function.                                             | Hard to test mapping without triggering ajax concerns; future save changes risk breaking unrelated behavior. | Split the save boundary into `buildProductionLineSavePayload`, `postProductionLineSave`, and the compatibility facade. |
| [x]  | P0       | Unsafe alert rendering          | `Alert` used `dangerouslySetInnerHTML`.                                                                                            | Alert messages were inserted as HTML.                                                                                         | A server/client error string could render unexpected markup.                                                 | Render alert messages as normal React text.                                                                            |
| [x]  | P0       | Debug/loose runtime code        | Runtime debug output and high-value `any` types made the production flow harder to trust.                                          | Production services accepted broad `any` arguments and the editor previously logged production rows.                          | TypeScript could not protect the calculation/save contracts well enough.                                     | Typed production planning and save contracts around existing domain types; no production row debug log remains.        |
| [ ]  | P1       | Production editor orchestration | `ProductionLineApp` is doing too much: state store, calculation coordinator, modal orchestration, analytics, save/import workflow. | The component owns many independent states and handlers.                                                                      | Future feature work will keep increasing coupling and duplicated update rules.                               | Extract `useProductionLineEditor` after P0 stabilizes.                                                                 |
| [ ]  | P1       | Analytics                       | Repeated analytics try/catch blocks are scattered through event handlers.                                                          | Many handlers inline `window.umami` access.                                                                                   | Noisy component code and inconsistent event payloads.                                                        | Add a tiny `trackProductionLineEvent()` helper.                                                                        |
| [ ]  | P1       | Visualization boundary          | Visualization adapter uses a fake table-handler and broad `any`.                                                                   | `VisualizationAdapter` builds a fake table object for `Visualization`.                                                        | Visualization changes are fragile and hard to type-check.                                                    | Define a typed visualization input facade and isolate Cytoscape/qtip `any` at the boundary.                            |
| [ ]  | P2       | Legacy DOM integration          | jQuery/React mixed modal behavior remains in some components.                                                                      | Settings/checklist code binds plugin handlers manually.                                                                       | Event cleanup and ownership bugs are easier to introduce.                                                    | Isolate legacy DOM/plugin code in wrappers.                                                                            |
| [ ]  | P2       | Generated JavaScript            | Generated JS chunks are easy to forget.                                                                                            | Webpack emits `public/js` bundles from TypeScript entrypoints.                                                                | TS source and served assets can drift.                                                                       | Run `npm run build` after TS changes and commit required emitted bundles.                                              |
